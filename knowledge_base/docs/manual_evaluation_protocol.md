# 手册问答的私有评测协议

检索、最终答案和 Listing 任务完成率分别报告。真实厂商资料、题目、答案、完整召回和运行数据库只放在已忽略的 `eval_private/`；本文件仅公开方法，不包含私有原文。

## 数据与版本

- 记录原 PDF、解析缓存、题目、协议、运行代码的摘要。原件保留，内容更正建立新版本。
- 每条证据由标准产品名与完整正文的 SHA256 标识，不使用数据库自增编号作为跨版本标签。
- 标注每个答案要点对应的原 PDF 页、章节和支持切片。PDF 存在而解析稿缺失的内容记为来源缺口，目录元数据不能替代正文证据。
- 对缺少设备信息的题，区分自由问答和已选手册场景。补上下文后的输入必须单独版本化，不能拿新旧分数直接计算提升。
- 开发题用于修系统。已经查看、分析过的冻结题只作为回归保留集；独立验收需另外建立未参与调试的数据。

## 分开计算

| 指标 | 判断方式 |
|---|---|
| 主体路由 | 是否识别可见输入中的产品；信息不足时是否正确澄清 |
| hit@1 / hit@3 | 排名前 1 / 3 的本地切片与标注相关证据集合是否有交集 |
| 证据覆盖 | 各要点对应的支持切片是否进入 top3 / 全部生成上下文 |
| 答案覆盖 | 逐条检查最终完整答案是否表达该事实；单独记录错误、矛盾和无证据声明 |
| 运行可靠性 | 库、向量化、模型或重排失败单列，不混进普通质量零分 |

引用的手册里同时讨论两个产品时，检索保留两个产品的候选集合。精确型号优先走目录别名匹配，相近型号和共享别名不得依靠一个未经校准的向量分数强行确认。

## 最小运行闭环

1. 校验忽略规则和来源摘要；确保本机索引正文与语料清单完全对应。
2. 预热一次本地向量模型；评测关闭联网，显式传入会话历史，并使用独立会话 ID。
3. 先运行开发题。每题立即保存全部召回、重排、答案、阶段错误和耗时。
4. 查看失败并完成必要修改；固定代码与协议后再运行回归保留集，不能根据保留集结果继续调参后仍称独立验收。
5. 对答案逐题复核，输出分项分数、错误归因和未验证边界，再决定是否扩展数据。

合成回归可从 `knowledge_base/` 运行：

```powershell
python -m unittest discover -s test/rag -v
```

这些测试覆盖型号边界、多产品检索、证据评分及数据库故障回退，不依赖真实手册或远端模型。

## 已暴露题的修复回归

已查看过的失败题可用于下一版开发，整批旧题随之仅用作开发回归。修复时保留原题、原标注和原运行；新运行记录代码、提示词与原始数据摘要，不将调试后的分数当作独立验收结果。

手册检索可在已确认产品范围内加入词语补充召回，按产品分配融合候选及最终上下文名额。重排使用展开跨行表格、去除图片链接的文本视图，证据身份仍由未经改写的完整正文决定。记录实际进入生成提示词的切片，避免把因字符预算被排除的文档计为生成证据。截断造成的缺失与未召回分别记录。

## 新手册的一次性验收

1. 先用已暴露的开发/回归题修复系统；记录代码、提示词、模型配置、语料及图片资产摘要。
2. 增加未参与旧题的手册，在原 PDF 中逐题核对新问题、答案要点、页码、正文证据和必要图示。出题及标注校对不调用被测问答系统。
3. 把新题、答案、来源清单及协议封存，生成 SHA256 清单。封存后不得依据这些题修改检索、提示词、评分口径或模型配置；任何变更都需另立验收版本。
4. 验收脚本在启动前核对封存摘要和系统版本；用原子运行锁只允许一次完整尝试，禁止挑题、续跑或覆盖旧结果。中断和基础设施错误保留记录，不因分数不好重跑。
5. 旧题回归与新题验收分别统计。总题量可以汇总为工作量，不能把旧题重新命名为独立验收。新题由同一作者出题和核对，应如实标明，不能称独立人工盲评。
6. 验收后只复核保存的答案、证据、路由及图片；若发现失败，报告失败并转为后续开发资料，本轮分数保留。

PDF 首页面版解析缺字时，以原生文本补充块恢复，记录 PDF 摘要、页码、提取方式和编码异常；目录别名不作正文证据。纯扫描页记录为待 OCR，不能声称原生文本恢复成功。

图片验收分开核对：原图文件、内容哈希、发布链接的 HTTP 状态与 MIME、实际上下文中的图片引用、同步/流式输出及浏览器真实加载。默认本机后端使用 `/manual-assets/<内容摘要>.<格式>`，旧图片版本保留；仅声明已实际验证的后端。MinIO 需单独验证，不能用本机通过替代。
